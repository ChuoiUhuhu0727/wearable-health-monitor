# Reproducibility and Evidence Guide

**Wearable Activity & Health Monitor — Subsystem: Firmware & AI**

This document allows any reader to independently verify every quantitative claim made in
the accompanying reports. For each reported number it states which script produces it, what
command to run, and what output to expect.

Nothing in the reports was computed by hand or transcribed from a one-off session. Every
figure and every table is generated by a script that can be re-run.

---

## 1. Environment and setup

**Requirements:** Python 3 with `pandas`, `numpy`, `scikit-learn`, `joblib`, `matplotlib`
and `scipy`.

All scripts use paths relative to the project root and expect this layout:

```
project_root/
├── <scripts>.py
├── data/processed/master_dataset.csv          the training dataset
├── experiments/wrist/valid_sessions/          original device recordings
├── experiments/wrist/participant_log.csv      participant index
├── experiments/wrist/session_manifest.csv     session status log
└── paper/figures/                             generated plots
```

**Determinism.** Every script fixes `random_state = 0`. There is no randomness anywhere in
the pipeline: running any script any number of times produces exactly the same output. Any
difference in a reader's output therefore indicates a difference in the input data or the
environment, not run-to-run variation.

**Runtime.** The activity classifier scripts complete in seconds. The heart rate scripts
resample and filter roughly 45,000 samples per participant and take one to two minutes each.

| 1 | `python scripts/dataset/build_processed_dataset.py` | `Wrote 20258 rows (16880 clean)`, 18 participants |

the reports, and writes the exported model to `models/activity_classifier.pkl`.

## 3. Reproducing the heart rate results

**These scripts must be run in this order.** Each step overturns the conclusion of the one
before it, and the sequence is itself part of the reported finding.

| Step | Command | The question it answers |
| :--- | :--- | :--- |
| 1 | `python scripts/analysis/lms_denoise_mvp.py` | The initial three-filter comparison: 26.95 / 26.96 / 29.83 / 29.96 bpm |
| 2 | `python scripts/analysis/check_ground_truth_sanity.py` | Is the reference measurement itself correct? **No** — it fails for 3 of 5 participants |
| 3 | `python scripts/analysis/hr_estimator_v2.py` | Does the corrected estimator pass the physiological check? Yes, for 4 of 5 |
| 4 | `python scripts/analysis/lms_denoise_v2.py` | Re-measuring with the corrected reference: signal yield 35.0% vs 9.6% |

Step 2 also writes the waveform figures used to distinguish a sensor fault from an algorithm
fault, and prints the beat-interval diagnostics (interval ratio 1.03, amplitude ratio 2.22)
that rule out the competing explanation.

An additional script, `check_hr_information_baseline.py`, compares the wrist estimate against
estimators that ignore the sensor entirely. It is not required to reproduce any reported
number but documents an intermediate step in the investigation.

## 6. Methodological choices, stated explicitly

These choices affect the reported numbers and are documented here so that they are visible
rather than buried in the code.

**Transition rows are excluded from all analysis.** Each session contains roughly 15 seconds
between activities while the participant changes posture. During that interval the recorded
label does not yet describe what the body is doing. Including those rows would inject
mislabelled data into both training and testing. After exclusion, 16,880 of 20,258 rows
remain.

**The baseline is computed on exactly the same rows.** `check_majority_baseline.py` applies
the identical filter, because a baseline computed on a different set of rows cannot be
compared against an accuracy measured on this one.

**Naturally occurring acceleration spikes are kept, not removed.**
`build_processed_dataset.py` flags them via an `is_outlier_spike` column but never deletes a
row. The objective is a model that works with real-world movement rather than with
laboratory-clean data.

**Invalid sessions are excluded structurally.** Sessions recorded while testing the device,
with nobody wearing it, are held in a separate directory that the dataset builder never
reads. `session_manifest.csv` records the status of every session and the reason for each
exclusion.

**Evaluation is user-independent.** All accuracy figures come from leave-one-participant-out
cross-validation, in which each participant is held out entirely as the test set in turn. A
random row-wise split would place adjacent time windows from the same person in both the
training and test sets and inflate the result.

## 7. Limits of this evidence

The following are stated so that the reported numbers are not read as establishing more than
they do.

**The heart rate conclusion rests on signal yield, not on the error table.** After correcting
the reference, only 19–38 windows had a valid reading on both channels simultaneously. That
sample is too small to rank the four filter configurations statistically. The figure that
should be cited from the heart rate subsystem is the signal yield rate, not the mean absolute
error.

**The acceptance threshold is a choice made by the authors.** The signal yield figures depend
on a coefficient-of-variation threshold of 0.25. The full range was swept to confirm that the
direction of the conclusion does not change, but the absolute percentages do depend on it.

**The reference channel is not a clinical standard.** Even after correction, the fingertip
estimator still fails the physiological check for one of five participants. A clinical-grade
reference would require an electrocardiogram.

**Waveform figures are drawn from participants with raw capture only.** Five of the eighteen
participants have full raw signal recordings. Figures showing raw waveforms and feature
distributions are computed from those five, not from all eighteen.

## 8. Inventory of data and code

| Item | Content |
| :--- | :--- |
| `data/processed/master_dataset.csv` | Training dataset — 20,258 windows, 18 participants |
| `experiments/wrist/valid_sessions/` | Original device recordings, never edited by hand |
| `experiments/wrist/participant_log.csv` | Participant index and protocol version per session |
| `experiments/wrist/session_manifest.csv` | Status of every recorded session, including exclusions |
| `firmware/ble/main.cpp` | Device firmware; feature computation at lines 738–750 |
| `train_activity_classifier.py` · `.ipynb` | Model training and evaluation; the notebook version carries the same analysis with plots and saved output |
| `check_*.py` | Verification scripts, one per claim |
| `lms_denoise_mvp.py` · `lms_denoise_v2.py` | Filter comparison before and after the reference correction |
| `hr_estimator_v2.py` | The corrected heart rate estimator |
| `plot_*.py` | Figure generation |
| `paper/figures/` · `paper/figures_en/` | Generated plots, Vietnamese and English |

**A note on the raw data.** Original recordings are treated as immutable. No processing step
edits them; every derived dataset is produced by a script that can be re-run from the
originals. This convention is what allowed the entire heart rate analysis to be recomputed
from scratch after the reference measurement was found to be faulty.
